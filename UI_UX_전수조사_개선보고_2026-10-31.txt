툴팁·입력 안내·Text.rich 호출은 native-labels.txt에 추가 기록하고 코드를 점검했다.

기존 UI·저장·안내서·어절 줄바꿈 회귀 검사도 수행했다.

2. 반영한 개선
A. 한글 제목의 문장부호 표시
비교 안내, 홈 제목, 결과 제목, 기록 제목의 음수 자간을0으로 정리했다.
호스트 측정에서 어절 결합 문자가 음수 자간을 추가로 적용받아 문장 폭이 의도보다 좁아지는 현상을 확인했다.
예:23px/자간-0.7의 '어느 쪽이 더 클까요?'는 일반 텍스트210.4369px, 결합 텍스트206.9369px였다.
자간0에서는 둘 다218.8369px로 같았다. probe JSON/PNG에 근거를 보존했다.
수정 후 호스트에서는 물음표와 마침표를 확인했다.
실제 삼성 폰트의 정확한 잘림 원인을 확정하거나 실기기 수정 검증을 완료했다고 표현하지 않는다.
조사 초기에 연결된 폰의 현재 화면을 읽기 전용 캡처했다. 이후 연결이 끊겨 해당 폰트 추가 대조는 하지 못했다.

B. 탭과 다음 문제 전환
원래부터 AppController.start에서 곱셈18개/나눗셈15개를 모두 생성하고 있었다.
다음 문제로 넘길 때 Generator를 호출하는 구조가 아니었고, 탭마다 파일 저장도 하지 않았다.
선택 후420ms 기다리던 자동 전환을100ms로 줄였다. 선택 상태는 먼저 반영한다.
부분 분수 정렬은 자동 이동하지 않고4개 선택 완료 때만 이동하는 규칙을 유지했다.
공통 WordText의 동일 텍스트·폭·배율·방향별 어절 배치 계산을 최대4개까지 재사용한다.
원문/스타일이 바뀌면 캐시를 비우며 폭·배율·방향별 키를 구분한다.
이는 반복 어절 측정 비용을 줄이는 수정이며, 실기기의 프레임 지연이 모두 해결됐다는 성능 측정 결과는 아니다.

C. 기록 버튼
비타민 각 연습 카드의 글자형 기록 진입을 아이콘·배경·테두리가 있는 OutlinedButton으로 바꿨다.
기록 기능과 회차/정답률/분 단위 소요시간 데이터는 유지했다. 시작 화살표와 별도 동작으로 유지한다.
기록 버튼의 최소48dp 터치 영역과 화면 내 도달 가능성을 검사했다.

D. 조사 중 추가 정리
설정의 'GRIT  1.2.0' 하드코딩을 'GRIT'로 바꿔 잘못된 버전 정보를 없앴다.
비교 화면의 이전 문제 아이콘에 '이전 문제' 접근성 이름을 추가했다.

3. 추가 개선 후보 — 이번에는 조사 기록만 남김

우선순위2: 작은 보조 문구의 대비
muted(#69776E)는 paper(#F6F5F0) 위 대비가 계산상4.31:1, 흰색 위4.70:1이다.
같은 색이더라도 배경에 따라 읽기 쉬움이 달라진다. #65736A 정도로 조금 진하게 하면 paper 위 약4.57:1이 된다.
이번에는 색상 변경을 적용하지 않았다. contrast.json 참조.

우선순위3:30개 Set 목록 이동
현재 난도순 정렬은 완료됐지만 긴 목록 아래쪽까지 찾아 내려가야 한다.
난도 구간 이동이나 Set 번호 바로가기가 다음 개선 후보다. 기존 Set ID·완료 기록을 유지하는 방식으로 검토한다.

4. 검사 결과와 실패 이력
최초 묶음 실행43통과/1실패. 실패는 새 캡처 도우미가 비동기 목록 로딩 중 pumpAndSettle을 호출한 시간 초과였다.
대기 방식을 보완한 해당 파일4항목 재실행을 통과했다. 이미지 로딩 완료 검사까지 보강한 최종4항목도 통과했다.
중복 재실행을 제외한44개 검사 항목에 성공 실행 근거가 있다.44개 단일 실행 전체 PASS 로그라고 주장하지 않는다.
정적분석의 새 검사 코드 스타일 경고1개를 정리했고 최종 분석은 No issues found다.
초기진단 테스트 중단 로그, 초기 실패, 재실행 로그를 삭제하지 않았다.
이전900 콘텐츠·이미지3128개 자산(sets.json 제외)을1.3.1 APK와 바이트 대조해 일치했다.
Set ID/문항 연결/난도는 그대로이며 앞선 난도순 order 변경만 존재한다.
기존 release APK SHA256도 일치한다. 저장/스냅샷/정답/메모 형식과 비타민 계산·채점 규칙을 변경하지 않았다.
실제 폰의 저장 데이터를 읽거나 수정하거나 앱을 설치하지 않았다. 캡처 외 기기 조작 없음.
